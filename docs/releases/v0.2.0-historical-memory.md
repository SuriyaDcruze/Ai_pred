# Release v0.2.0 — Historical Memory

- **Tag:** `v0.2.0-historical-memory`
- **Date:** 2026-07
- **Sprint:** 2 (COMPLETE)
- **Highlights:** the Historical Memory Engine — Aegis' permanent, queryable knowledge layer
  over every completed prediction.

Builds directly on `v0.1.0-forward-testing`. It adds the machinery to enrich each completed
prediction into a retrievable **Memory Record**, aggregate performance by many dimensions,
and serve it over REST — all **additively**, changing nothing about how predictions are made
or resolved.

## Features
- **Satellite schema** (migrations `0002`–`0005`) over the existing `prediction_history.db`:
  `memory_reasoning`, `memory_embeddings` (vector placeholder), `memory_aggregates`, plus
  additive retrieval indexes on `predictions`. `predictions` itself is untouched.
- **Memory Store** (`app/memory/store.py`): thread-safe, idempotent CRUD over the satellite
  tables, with typed errors and structured logging.
- **Memory Builder** (`app/memory/builder.py` + `aggregates.py`): enriches completed
  predictions into reasoning + embedding-placeholder rows, computes derived aggregates (by
  overall/symbol/sector/regime/timeframe/confidence and per model version), and **backfills**
  (idempotent). Reads via `PredictionStore`, writes via `MemoryStore` only.
- **Retrieval Engine** (`app/memory/retrieval.py`): composes Memory Records **on read**;
  filtered search with deterministic **keyset pagination**; read-only aggregate queries; the
  **similarity contract** (explicit "unavailable"); and a bounded, honest **GPT context
  bundle**.
- **REST API** (`/memory/*`, 9 endpoints): record, search, statistics, timeline, similar,
  context, build, backfill, rebuild-aggregates — thin transport, generated OpenAPI. Full
  reference: [../api/historical-memory.md](../api/historical-memory.md).

## Improvements
- **Honesty preserved:** `/memory/statistics` and `/memory/context` always report sample size;
  `/memory/similar` never fabricates a score.
- **Five new ADRs** (0007–0011): satellite architecture, compose-on-read, retrieval-via-store,
  thin API, similarity-contract.
- **Documentation:** Volume 13 & 21 updated to as-built; full API reference; Sprint 2 report;
  this release note.
- **Testing:** 110 Historical Memory tests added; full suite **471 passed**. Import-guard +
  no-write + migration tests prove Sprint 1 and both engines untouched.

## Breaking changes
**None.** All changes are additive:
- New package `app/memory/`, new router `/memory/*`, four new migrations (new tables + indexes
  only), and lifespan wiring in `app/api/main.py`.
- `predictions`, `/forward/*`, the dashboard, and the Prediction/Outcome/Risk engines are
  unchanged. `data/prediction_history.db` migrates forward automatically on first run.
- Version bumped `0.1.0` → `0.2.0` (reported by `/health` and the API title).

## Known limitations
- **Memory is only as full as the live sample** — Forward Testing's sample is still
  accumulating (auto-record + monitor wiring is Sprint 1 tech debt), so memory is near-empty in
  production until then. Every path handles the empty state.
- **Embeddings are storage-only** — vectors are `NULL`; nothing computes them yet (Vol 14), so
  `/memory/similar` is deliberately "unavailable".
- **Retrieval filters in-app** (not via the new `predictions` indexes) — correct/fast now;
  indexes are forward-investment (ADR 0009).
- **`memory_news` deferred**, **no memory dashboard**, **SQLite single-writer** (Postgres is
  the future path, Vol 21).

## Upgrade notes
No action required. On first run the app creates/migrates the satellite schema automatically.
To populate memory for predictions that resolved before this release, call
`POST /memory/backfill`.
