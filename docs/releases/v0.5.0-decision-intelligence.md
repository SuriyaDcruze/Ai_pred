# Release v0.5.0 — Decision Intelligence Engine

- **Tag:** `v0.5.0-decision-intelligence`
- **Date:** 2026-07
- **Sprint:** 5 (COMPLETE)
- **Highlights:** the **Decision Intelligence Engine** — one **explainable, evidence-bound** object
  that **composes** the four prior engines (Prediction/Outcome verdict + Historical Memory + Similarity
  + Learning), explains it, rates the **quality of its evidence**, and serves it at `/intelligence/*`.
  Deterministic, read-only. **No training, no prediction, no advice, no new edge.**

Builds on `v0.4.0-learning-engine`. It adds a new read-only composition/serving layer **additively**,
changing nothing about how predictions are made, resolved, stored, retrieved, or learned from.
Distinct from the legacy live-analysis intelligence (`app/intelligence.py`, `app/sector.py`, Vol 08),
which is untouched (ADR 0023).

## New functionality
- **Domain model & contract** (`app/decision_intelligence/models.py`): the deterministic, versioned
  `DecisionIntelligence` object; canonical states `EMPTY`/`INSUFFICIENT_DATA`/`PARTIAL`/`COMPLETE`/
  `STALE`/`ERROR`; `di-1` + upstream-version stamps; the per-subsystem composition contract; immutable
  `decision_id` + SHA-256 checksum.
- **Composition Engine** (`compose.py`, `providers.py`): reads each engine's existing output verbatim
  into its own section (fixed pipeline order); graceful degradation (thin → `INSUFFICIENT_DATA`,
  errored → `ERROR`, never fails the whole object); `LearningPipelineProvider` reuses the Learning
  Engine's own pipeline. Recomputes nothing.
- **Evidence & Explanation Engine** (`evidence.py`): a deterministic evidence graph (root → subsystem
  → facet), a provenance resolver (no orphans), a For/Against breakdown, a missing-evidence list, and
  a descriptive explanation + disclaimer.
- **Composite Confidence & Prioritisation** (`confidence.py`): an **evidence-quality** indicator (how
  trustworthy/complete/consistent the assembled evidence is — **not** a probability of success or a
  trading signal), conflict detection, and a deterministic `prioritise()`.
- **REST API** (`/intelligence/*`, `app/api/intelligence.py`): `GET /intelligence/{prediction_id}`,
  `/symbol/{symbol}`, `/health`, `/version`. Full reference in
  [the as-built volume](../architecture/decision-intelligence-engine.md).

## Architecture improvements
- **Six ADRs** (0023–0028): Decision Intelligence Engine; read-only composition (reuse, never
  recompute); evidence-based explanation; composite confidence as evidence quality; thin REST
  transport; versioning + compose-on-read.
- **Reuse, not reinvent:** composed figures equal their source engines' figures (no drift).
- **Honesty preserved:** graceful degradation to prediction-only; conflicts recorded (never hidden);
  descriptive not prescriptive; no new edge/advice claim.

## API additions
- Four `/intelligence/*` endpoints (above). Responses carry the composed object + evidence +
  explanation + confidence + prioritisation + versions + **domain checksums**; **deterministic**
  (stable content only, no wall-clock ⇒ byte-identical for identical objects). Error taxonomy: `400`
  bad id/symbol · `404` unknown prediction/symbol · `409` schema-version mismatch · `422` malformed ·
  `503` dependencies unavailable. Single owner of the `/intelligence/*` sub-namespace; the legacy
  exact `GET /intelligence` is untouched.

## Database usage
- **No migration.** The engine is **compose-on-read** and writes nothing (Sprint 3 precedent). An
  optional append-only `decision_intelligence_runs` audit/snapshot table was **deferred**. No Sprint
  1–4 table is changed.

## Testing
- 88 Decision Intelligence tests added; full suite **777 passed, 0 failed**. Import-guard, no-write,
  reuse-not-recompute, determinism, and unchanged-Sprint-1–4 tests prove isolation.

## Breaking changes
**None.** All changes are additive: a new package, a new router (one `include_router` line), and the
version bump `0.4.0` → `0.5.0`. No existing endpoint, table, engine, or migration changes.

**Sprint 1–4 interfaces are unchanged** — `/forward/*`, `/memory/*`, `/memory/similar*`, and
`/learning/*` behave exactly as before; the Prediction/Outcome/Risk engines, `predictions`, and every
prior table are byte-for-byte unchanged (Sprint 5 reads them, never writes). **Forward compatibility:**
the `decision_intelligence_version` (method), the recorded upstream versions (staleness), and the API
`schema_version` (payload) evolve independently; a request for a non-served `schema_version` returns
`409`.

## Migration notes
No action required. On first run the `/intelligence/*` API composes everything **on read** from
existing data; nothing is created or migrated. On today's near-empty corpus every composed object
degrades honestly to "prediction + outcome verdict, with `INSUFFICIENT_DATA` for historical context"
until Forward Testing accumulates a real record.

## Known limitations
- Memory/Similarity/Learning are near-empty in production until Forward Testing populates the corpus
  (Sprint 1 tech debt) — the engine correctly says `INSUFFICIENT_DATA` until then.
- The API recomputes the pipeline per request (deterministic ⇒ consistent); a cache / snapshot store
  is a future scale option.
- **Descriptive only — no predictive edge is claimed.** Consistent with `docs/RESULTS.md`, the only
  verified edge remains the Outcome Engine (backtest-only). The Decision Intelligence Engine composes
  and explains existing evidence — it manufactures no edge.
