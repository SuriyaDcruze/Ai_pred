# Release v0.7.0 — Agent Engine

- **Tag:** `v0.7.0-agent-engine`
- **Date:** 2026-08
- **Sprint:** 7 (COMPLETE)
- **Highlights:** the **Agent Engine** — a **deterministic planning + permissioned tool-execution**
  layer that orchestrates the existing read-only AEGIS engines **as tools**, with an explicit approval
  gate and a full immutable **audit trail**. It **never predicts or advises** and invokes no engine
  directly. Deterministic, permissioned, auditable.

Builds on `v0.6.0-conversation-intelligence`. Adds a new agent layer **additively** — nothing about
how predictions are made, resolved, stored, retrieved, learned from, composed, or explained changes.
Distinct from the legacy `app/chat/` and the Conversation Engine (ADR 0035).

## Overview
A 6-module package (`app/agent/`) — **Domain Model → Tool Registry → Planner → Permission Engine →
Executor → LLM Planning Adapter** — served at `/agent/*`. Tools are a **metadata catalog** over the
existing engines; the Planner builds plans from that metadata only; the Permission Engine authorizes
each step (with a metadata **safety floor** so a state-changing tool can never be authorized below
`APPROVAL_REQUIRED`); the Executor runs only approved steps through a **replaceable, registry-gated
invoker** (the shipped one is an offline deterministic stub — no engine); the LLM adapter is
**advisory only** and the deterministic Planner remains the authority. It imports neither the
Prediction nor the Outcome engine and gives **no advice and no predictions**.

## New capabilities
- **Agent domain model** (`models.py`, `agt-1`): `Agent`, `AgentSession` (frozen, checksummed,
  validated lifecycle), `AgentTask`, `AgentPlan`, `ExecutionStep`, `ToolCall`, `ToolResult`,
  `PermissionRequest`, immutable `AuditEntry`; deterministic ids; serialization.
- **Tool Registry** (`tools.py`, `tool-1`): `ToolDefinition`/`ToolSchema`/`ToolParameter`;
  `ToolCategory`/`ToolCapability`/`ToolAvailability`; immutable functional `ToolRegistry`; WRITE ⇒
  permission-required invariant; read-only `default_registry()` (7 tools). **Metadata only.**
- **Deterministic Planner** (`planner.py`, `plan-1`): `AgentTask` → `AgentPlan` from registry metadata
  only; rule-based selection; cycle-detecting topological ordering; full error taxonomy.
- **Permission Engine** (`permissions.py`, `perm-1`): policy-driven `ALLOWED`/`APPROVAL_REQUIRED`/
  `DENIED`; ordered first-match `PermissionPolicy`/`PermissionRule`; **safety floor** (policy tightens
  only); `PermissionRequest` per approval, left `PENDING`.
- **Executor** (`executor.py`, `exec-1`): runs only approved steps in plan order via a replaceable
  `ToolInvoker` (offline `EchoToolInvoker`, **no engine**); dependency-aware skipping; immutable
  ordered audit; SUCCESS/SKIPPED/DENIED/FAILED aggregation.
- **LLM Planning Adapter** (`planning_llm.py`, `planllm-1`): provider-independent, **advisory-only**
  (`EchoPlanningProvider` + `OpenAIPlanningProvider`/`azure_openai`, duck-typed, **no SDK import**);
  response validation; normalised error taxonomy; the Planner validates every suggestion.
- **REST API** (`/agent/*`, `app/api/agent.py`, `agent-api-1`): 9 endpoints.

## Architectural changes
- **Seven ADRs** (0035–0041): Agent Engine; Tool Registry; deterministic Planner; permission model;
  Executor; advisory LLM planning; REST API ownership.
- **Read-only by default + no advice/prediction**: imports neither engine; the shipped invokers are
  offline stubs; no writes; no migration.
- **Permissioned + auditable**: no tool runs without an approved `PermissionRequest`; every execution
  action is an immutable ordered `AuditEntry`.

## API additions
- Nine `/agent/*` endpoints: `POST /agent/session`, `GET`/`DELETE /agent/session/{id}`,
  `POST /agent/plan`, `POST /agent/authorize`, `POST /agent/execute`, `POST /agent/suggest`,
  `GET /agent/health`, `GET /agent/version`. Artifact-passing pipeline (plan → authorize → execute).
  Error taxonomy: planner `404/409/422` · permission `400/422` · execution `422/409/502` · malformed
  payload `400` · provider faults normalised **in-body**; internal exceptions **never** leaked. Full
  OpenAPI.

**Sprint 1–6 interfaces are unchanged** — `/forward/*`, `/memory/*`, `/memory/similar*`,
`/learning/*`, `/intelligence/*`, `/chat/*`, the Prediction/Outcome/Risk engines, `predictions`, every
prior table, and the legacy `POST /chat` all behave exactly as before. Integration point: the Agent
Engine describes those engines as **tool metadata** and (in future) invokes them read-only under
permission — today the shipped invoker is an offline stub.

## Breaking changes
**None.** All changes are additive: a new package, a new router (one `include_router` line), and the
version bump `0.6.0` → `0.7.0`. No existing endpoint, table, engine, migration, or the legacy
`POST /chat` changes.

## Migration / upgrade notes
No action required. `/agent/*` composes everything **in memory** from the default tool catalog; nothing
is created or migrated. The shipped `EchoToolInvoker` (execution) and `EchoPlanningProvider`
(suggestions) are clearly-marked offline stubs; wire a real engine-backed invoker
(`app.state.agent_pipeline`) and an LLM provider (`app.state.agent_planning_adapter`) to enable live
tool execution and suggestions.

## Known limitations
- Offline invokers by default (execution + suggestions); real ones need thin translators + credentials.
- In-memory agent sessions (per-process; no persistence).
- **No new edge, no advice.** Consistent with `docs/RESULTS.md`, the only verified edge remains the
  Outcome Engine (backtest-only). The Agent Engine orchestrates existing read-only capabilities under
  permission and audit; it manufactures no edge.

## Future roadmap
Wire engine-backed `ToolInvoker`s (read-only, under permission); a real LLM planning provider; optional
session/audit persistence; richer planning rules as the tool catalog grows.
