# Release v0.3.0 — Similarity Engine

- **Tag:** `v0.3.0-similarity-engine`
- **Date:** 2026-07
- **Sprint:** 3 (COMPLETE)
- **Highlights:** the Similarity Engine — *"I have seen this setup before"* over Historical
  Memory, as **explainability** (not a predictive edge), fully **deterministic**.

Builds on `v0.2.0-historical-memory`. It fills the `memory_embeddings` placeholder and lights
up the `/memory/similar` contract — **additively**, changing nothing about how predictions are
made, resolved, or stored.

## New functionality
- **Feature Vector Builder** (`app/similarity/feature_vector.py`): a Memory Record → a
  deterministic, versioned numerical vector (`sim-fv-1`, dim 100). Fixed one-hot vocabularies,
  stable SHA-1 hashing, clamped min-max scaling, present flags.
- **Embedding Generator** (`app/similarity/embedding.py`): the L2-normalised feature vector
  (`sim-emb-1`) stored in `memory_embeddings`; generate / store / rebuild / **backfill**
  (idempotent). No training.
- **Similarity Search** (`app/similarity/search.py`): cosine k-NN, **filter-first then
  brute-force**, with honest neighbour statistics (win rate, avg R, outcome distribution) and a
  logged candidate cap. Read-only.
- **Retrieval integration** (`app/memory/retrieval.py`, additive): the search engine is
  injected into `RetrievalEngine`, activating `similar()` / `similar_by_embedding()`.
- **REST API** (`/memory/similar*`, `app/api/similarity.py`): `GET /memory/similar/{id}`,
  `GET /memory/similar?prediction_id=`, `POST /memory/similar/search`, `GET /memory/similar/
  health`. Full reference in [Volume 14](../architecture/14-similarity-engine.md).

## Architecture improvements
- **Five ADRs** (0012–0016): deterministic feature vectors; deterministic embeddings;
  similarity-engine architecture; retrieval integration via optional DI; similarity REST API.
- **No import cycle** between `RetrievalEngine` and the search engine (setter DI + lazy import).
- **Honesty preserved:** every result carries a sample size; no fabricated scores; similarity is
  documented as explainability, not a trading signal.

## API additions
- Four `/memory/similar*` endpoints (above). Responses expose neighbours + scores + honest
  summary + engine versions — **never** raw embeddings or feature vectors. Error taxonomy:
  `400` validation · `404` prediction/embedding · `409` version mismatch · `503` engine
  unavailable.

## Database usage
- **No new migration.** Sprint 3 fills the `memory_embeddings` table provisioned in Sprint 2
  (M1 `0003`). Embeddings are unit-length float32 vectors; `embedding_version`/`feature_version`
  are packed into `model_name`; embedding generation is idempotent and rebuildable.

## Testing
- 98 Similarity Engine tests added; full suite **567 passed, 0 failed**. Import-guard,
  no-write, and unchanged-Sprint-1/2 tests prove isolation.

## Breaking changes
**None functionally.** All changes are additive. One internal move: the `/memory/similar/{id}`
route moved from `app/api/memory.py` to `app/api/similarity.py` (single route owner). At the app
level the endpoint still exists (now richer, and live); other `/memory/*` endpoints are
unchanged. Version bumped `0.2.0` → `0.3.0`.

## Migration notes
No action required. On first run, embeddings are absent (vectors `NULL`); generate them for the
existing corpus via the Embedding Generator's `backfill_embeddings()` (or as memory grows). The
Prediction/Outcome/Risk engines, `predictions`, and `/forward/*` are unchanged.

## Known limitations
- Brute-force search (no ANN in SQLite; logged cap); pgvector is the future scale path.
- Memory is near-empty in production until Forward Testing populates it (Sprint 1 tech debt).
- **Explainability only — no predictive edge is claimed** (the legacy kNN similarity added
  none on the untouched test).
