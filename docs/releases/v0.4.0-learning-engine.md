# Release v0.4.0 — Learning Engine

- **Tag:** `v0.4.0-learning-engine`
- **Date:** 2026-07
- **Sprint:** 4 (COMPLETE)
- **Highlights:** the **Behavioural Learning Engine** — honesty-gated **descriptive analytics**
  over completed Historical Memory (patterns → statistics → evidence-bound recommendations),
  exposed at `/learning/*`. **No training, no prediction, no advice.** Fully **deterministic**.

Builds on `v0.3.0-similarity-engine`. It adds a new read-only analytics layer **additively**,
changing nothing about how predictions are made, resolved, stored, or retrieved. Distinct from the
legacy meta-model retrainer (`app/training/`), which is the *other* Volume 15 sense and is
untouched (ADR 0017).

## New functionality
- **Learning Dataset Builder** (`app/learning/dataset.py`): completed Memory Records → a
  deterministic, versioned `LearningDataset` (`lds-1`/`lrn-1`), computed on read; SHA-256 checksum;
  `INSUFFICIENT_DATA` below `min_corpus`. Read-only.
- **Pattern Extraction** (`app/learning/patterns.py`): groups the dataset along an extensible
  dimension registry into deterministic **candidate** patterns — metadata + evidence only, every
  one a `HYPOTHESIS` (never `VALIDATED` here).
- **Statistical Validation** (`app/learning/statistics.py`): reuses the Sprint 2 aggregate math and
  **adds** a 95% **Wilson confidence interval**, a two-proportion **significance** test, an
  extensible **multiple-comparison correction** (Benjamini–Hochberg / Bonferroni / none), and a
  **consistency** score. A pattern is `VALIDATED` only if it clears `min_sample` **and** is
  significant *after* correction **and** its interval excludes the baseline — else `HYPOTHESIS` /
  `INSUFFICIENT_DATA`.
- **Recommendation Engine** (`app/learning/recommendations.py`): turns VALIDATED patterns into
  **evidence-bound descriptive** observations — plain-language summary + verbatim statistical basis
  + supporting `prediction_id`s + always-non-empty limitations; a **communication-confidence**
  label (`HIGH`/`MEDIUM`/`LOW`) that is **independent of statistical significance**. Never advice.
- **REST API** (`/learning/*`, `app/api/learning.py`): `GET /learning/summary`, `/patterns`,
  `/statistics`, `/recommendations`, `/evidence/{recommendation_id}`, `/health`, and
  `POST /learning/run`. Full reference in [Volume 15](../architecture/15-learning-engine.md).

## Architecture improvements
- **Six ADRs** (0017–0022): Behavioural Learning separation; read-only guarantee; statistical
  honesty model; recommendation philosophy; thin stateless REST API; versioning & append-only
  storage.
- **Reuse, not reinvent:** the base rollups reuse Sprint 2's aggregate math (regression-asserted),
  so validated figures cannot drift from `memory_aggregates`.
- **Honesty preserved:** nothing below `min_sample`; every rate carries an interval; multiple
  comparisons corrected; recommendations are descriptive hypotheses with mandatory limitations.

## API additions
- Seven `/learning/*` endpoints (above). Responses carry a metadata envelope (`schema_version`,
  `learning_version`, `dataset_version`, `generated_at`) + domain checksums; list endpoints
  support filtering + deterministic pagination. Error taxonomy: `400` bad filter/param · `404`
  unknown recommendation · `409` version mismatch · `422` type/bounds · `503` engine unavailable.
  Never exposes vectors, embeddings, or internal reasoning.

## Database usage
- **Four new append-only migrations** — `0006 learning_runs`, `0007 learning_patterns`, `0008
  learning_pattern_stats`, `0009 learning_recommendations` — each its **own** satellite table in
  the existing `prediction_history.db`. **No Sprint 1–3 table is changed.** All learning tables are
  **derived + rebuildable**; through this release the engine is **read-only** and writes nothing
  (the tables are provisioned for a future persisting run).

## Testing
- 122 Learning Engine tests added; full suite **689 passed, 0 failed**. Import-guard, no-write,
  reuse-regression, migration-integrity, and unchanged-Sprint-1/2/3 tests prove isolation.

## Breaking changes
**None.** All changes are additive: a new package, a new router (one `include_router` line), four
append-only migrations, and the version bump `0.3.0` → `0.4.0`. No existing endpoint, table, or
engine changes behaviour.

## Migration notes
No action required. On first run the four learning tables are created empty; the engine computes
everything **on read** from existing Historical Memory. On today's near-empty corpus every endpoint
honestly returns `INSUFFICIENT_DATA` until Forward Testing accumulates a real record. The
Prediction/Outcome/Risk engines, `predictions`, `/forward/*`, `/memory/*`, and `/memory/similar*`
are unchanged.

**Forward compatibility:** the three learning version stamps evolve **independently** — a change
to the analysis *method* bumps `learning_version`; a change to a record's *shape* bumps the dataset
schema (`schema_version`); a change to the HTTP *payload* shape bumps the API schema. A stored
artifact whose `learning_version` no longer matches the engine is treated as stale, not silently
reused. Requesting a non-served `learning_version`/`schema_version` via the API returns `409`.

## Known limitations
- Memory is near-empty in production until Forward Testing populates it (Sprint 1 tech debt) — the
  engine correctly says `INSUFFICIENT_DATA` everywhere until then.
- The API recomputes the pipeline per request (deterministic ⇒ consistent); a cached last-run is a
  future scale option. `POST /learning/run` reports a deterministic run without persisting yet.
- **Descriptive only — no predictive edge is claimed.** Consistent with `docs/RESULTS.md`, the only
  verified edge remains the Outcome Engine (backtest-only). The Learning Engine surfaces honest
  historical observations for humans and the GPT layer to explain — it manufactures no edge.
